## 1. Action-gate approval client (governance — gates v0.6.0)
Setup per [`inter-island-wave.md`](inter-island-wave.md) §0–§3: two islands
`test-a`/`test-b`, a `test-a→test-b` link grant, `deploy` exposed. Stage a
**pending** action and a **destructive-tier** one (e.g. expose + request a
`drop-database`-class action so the gate classifies it destructive). Then:
```bash
dejima                 # open the dashboard
```
- [ ] header badge: `⚖ N cross-island action(s) … [V] review`
- [ ] badge is **red + "destructive!"** when a destructive is pending; **amber** otherwise
- [ ] `V` → approvals overlay opens
- [ ] rows tier-colored: benign **muted** · mutating **amber** · destructive **bold-red ⚠**
- [ ] `v` on the selected row → expands full payload (topic + params)
- [ ] `a` on a **mutating** row → approves immediately
- [ ] `a` on a **destructive** row → demands a typed **`y`** (refuse to approve on a bare keypress)
- [ ] `d` → optional-reason prompt → deny
- [ ] `r` on a non-destructive row → `<max> [<ttl>]` prompt → approve **+ rule**
- [ ] `r` on a destructive row → no-op (no rule offered)
- [ ] `Tab` → rules region; `x` → revokes the selected rule
- [ ] after each decision: `dejima audit --verify` shows the matching `link.*` line, chain intact
- [ ] overlay matches the CLI: `dejima link approvals` and `dejima policy ls` agree
- [ ] **agent can't self-approve:** from inside `test-a`, the approve route is denied
  ```bash
  dejima exec test-a -- sh -lc 'curl -s -o /dev/null -w "%{http_code}\n" -X POST \
    -H "Authorization: Bearer $DEJIMA_TOKEN" "http://$DEJIMA_HOST/v1/link/actions/<id>/approve"'
  #   EXPECT: 403/404
  ```
- [ ] **wake-on-message** (the key unknown — see inter-island-wave §6): a sent
  message wakes an idle Claude Code agent (injected `📬 …` line, prompt not
  corrupted), does NOT interrupt a busy agent mid-turn, and wakes a hibernated
  island.

## 2. TUI navigation
- [ ] **Enter on an island** → opens **all its attachable agents**, one tab each
- [ ] island with **>4 attachable agents** → Enter **asks to confirm** before opening
- [ ] Enter on an island over **plain SSH / non-GUI** → falls back to the in-island shell (no window spawn)
- [ ] **`$`** on an island → in-island `/workspace` shell (contained)
- [ ] **`H`** → host terminal (uncontained, on the daemon host)
- [ ] Enter on a **headless** agent → opens its logs
- [ ] attach to an agent → the terminal **tab title** becomes `island/agent`
- [ ] attach via `$` → tab title `island — shell`

## 3. Dashboard visuals
- [ ] each island has a **stable color + glyph** (unchanged across a restart)
- [ ] agents read as a group under their island
- [ ] **agent state words align in a column** (`working`/`needs you`/`idle` start at the same column) regardless of name/type width
- [ ] **`i`** on an island → color/glyph **editor**: `Tab` switches axis, `←/→` choose, `Enter` applies
- [ ] applied identity **persists** (survives a dashboard refresh + a daemon restart)
- [ ] **`x`** in the editor clears → reverts to the deterministic default
- [ ] update bar lifecycle: green "updated" **auto-fades**; orange "restart to apply" **sticks**; red **retry** on a failed update
