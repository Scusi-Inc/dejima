# Lane 0.5-Hardening — Keychain secrets + idle auto-hibernate

You are the **Hardening** agent for the 0.5 wave. Two self-contained quality items.
Independent of the other lanes.

**Read first:** `docs/roadmap.md` (v1.x hardening items + the Versioning map → 0.5),
`internal/api/webhooks.go` (HMAC secrets), `internal/providercreds` / `internal/githubid`
(how secrets are stored today), `internal/service/`.

**Scope:**
1. **Secrets at rest via Keychain / Secret Service** — move webhook HMAC secrets and
   any dejima-held tokens out of plaintext config into the OS keychain (macOS
   Keychain; libsecret/Secret Service on Linux), with a file fallback. Note the
   headless-boot-vs-locked-keychain caveat already in the roadmap: detect the locked
   case and degrade gracefully (don't hard-fail as "never logged in").
2. **Idle auto-hibernate** — opt-in threshold ("hibernate after N hours with no
   attached client and no live agent process"). Reuse the agent-liveness + presence
   signals already surfaced on island detail. Off by default; configurable.

**Owns:** the keychain abstraction (new `internal/secrets` or similar) + its call
sites, the idle-hibernate logic (daemon-side timer + config), their CLI/flags.
**Don't touch:** session/reconnect, SDK, onboarding wizard, audit/auth/MCP internals
beyond reading where secrets currently live.

**Verify on Minion:** keychain round-trip on real macOS; idle-hibernate fires after
the threshold with no client/agent and wakes cleanly.

**Workflow:** branch `feat/hardening-keychain-idle`; `go build`/`vet`/`golangci-lint
run ./...`/`go test ./...` green; PR to `master`; commit only your hunks.
