Build an agent notifier in 40 lines

You don't want to sit and watch a dashboard to catch the moment an agent finishes or gets stuck. Let it tell you. Dejima emits a webhook for every agent event, so a tiny server can turn "task complete" into a push on your phone. Here's the whole thing.

What Dejima sends you

Subscribe a URL and Dejima POSTs it a small JSON object for every event. Each looks like this:

{ "type": "agent.task-complete", "island": "web", "agent": "a1",
  "payload": { ... }, "timestamp": "2026-07-01T18:22:04Z" }

The events worth a notification are the per-agent ones:

  • agent.waiting-for-input — the agent is stuck and needs you.
  • agent.task-complete — it finished what you asked.
  • agent.error — it hit an error.

There's more (island lifecycle, client attach/detach, agent.usage for token counts), but those three are the ones you'll want on your phone.

The notifier

A plain Node HTTP server, no framework and no SDK. It receives Dejima's events, keeps the three we care about, and forwards a one-line message to an ntfy topic (free push to your phone). Save it as notifier.mjs:

import http from 'node:http'

const NTFY = 'https://ntfy.sh/your-private-topic'   // your ntfy topic
const NOTIFY = new Set([
  'agent.waiting-for-input', 'agent.task-complete', 'agent.error',
])

http.createServer((req, res) => {
  if (req.method !== 'POST') { res.writeHead(405).end(); return }
  let body = ''
  req.on('data', c => (body += c))
  req.on('end', async () => {
    res.writeHead(204).end()                    // ack Dejima right away
    let ev
    try { ev = JSON.parse(body) } catch { return }
    if (!NOTIFY.has(ev.type)) return            // only what we care about

    const who = ev.agent ? `${ev.island}/${ev.agent}` : ev.island
    const msg = {
      'agent.waiting-for-input': `${who} needs you`,
      'agent.task-complete':     `${who} finished`,
      'agent.error':             `${who} hit an error`,
    }[ev.type]

    await fetch(NTFY, { method: 'POST', body: msg })   // ntfy shows the body as the push
  })
}).listen(8099, () => console.log('notifier listening on :8099'))

That's it. Run it next to your Dejima daemon (or anywhere on your tailnet the daemon can reach):

node notifier.mjs

Point Dejima at it

Subscribe your server's URL. Use the address the daemon can reach it on (localhost if it's on the same box, or the tailnet name otherwise).

dejima webhook subscribe --url http://localhost:8099

Now install the ntfy app on your phone and subscribe to the same topic. The next time an agent finishes or asks a question, your phone buzzes. Trigger one to check: give an agent a quick task and wait for the task-complete push.

Just want the raw event, no code? ntfy accepts a plain POST, so you can skip the server and point Dejima straight at your topic: dejima webhook subscribe --url https://ntfy.sh/your-private-topic. You'll get the raw JSON as the notification. The 30-line server above just makes it readable and lets you filter.

Where to take it

The same shape works for anything. Swap the fetch for a Slack incoming webhook, or a Discord one. Filter by ev.island to route different projects to different channels. Watch agent.usage to track token spend. And when you want to go past receiving events to actually driving islands, the Python and TypeScript SDKs wrap the same API the CLI uses.

Common questions

How do I get notified when my AI agent needs input?

Dejima emits an agent.waiting-for-input webhook event. Subscribe a URL with dejima webhook subscribe --url, and forward that event to a push service like ntfy. A server of about 30 lines does it; no SDK is required.

What events can I subscribe to?

Island lifecycle (created, running, hibernated, woken, purged), client attach and detach, and per-agent events: waiting-for-input, task-complete, error, and usage. You subscribe once and filter for the ones you want.

Do I need the SDK to build on Dejima?

No. Webhooks are plain JSON POSTs, so any HTTP server works. The Python and TypeScript SDKs help when you want to drive islands and attach to sessions programmatically, but a notifier only needs to receive events.
