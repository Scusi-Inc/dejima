Dejima

The substrate for multi-device agent workflows. pre-alpha

Dejima was an artificial island built in 1636 in Nagasaki Bay to serve as a quarantined trading post for foreigners during Japan's period of isolation.

Dejima is the missing layer for running AI coding agents on your own infrastructure. Each project lives in its own island — a contained container with the agent of your choice — drivable from any device on your tailnet via a clean CLI and brokered API.

In other words: it lets you run a bunch of Claude Code sessions on your own Mac mini or server without losing your mind to tmux.

You're SSH'd into your Mac mini. Five Claude Code sessions in tmux. Two are named claude1 and claude2 because you forgot. SSH drops, you reattach to the wrong window, and one of them just pushed to the wrong repo. There's a better way.

Architecture

┌──────────────────────────┐
│  Your devices            │   laptop · phone · web client
└────────────┬─────────────┘
             │  websocket over Tailscale
             ▼
┌──────────────────────────┐
│  Dejima daemon           │   on your Mac mini / VPS
└────────────┬─────────────┘
             │  isolation boundary
             ▼
┌──────────────────────────┐
│  Agent in an island      │   one container per project
└──────────────────────────┘

Inside each island, the agent process runs under a long-lived tmux session — that's what keeps it alive when no client is attached, and how multiple clients can share the same screen. The daemon bridges your websocket to that tmux session via a host-side PTY, which handles terminal sizing, multi-client multiplexing, and clean detach on disconnect.

Install

curl -fsSL https://aoos.github.io/dejima/install.sh | bash

Runs on macOS and Linux. Bootstraps Go + Docker as needed, builds the binaries, installs them to /usr/local/bin, builds the island image, registers the daemon as a service, runs a health check. Idempotent — re-run to update.

Use case: Home server

If you run AI agents over ssh on a home server — Mac mini, VPS, an always-on Linux box on your shelf — Dejima is the layer that fixes the parts of that workflow that suck.

Each project gets a named island. dejima init derives the name from the repo, dejima ls shows everything at a glance, and dejima connect <name> is the same command every time. No tmux mnemonics to memorize. No claude1/claude2 ambiguity.

dejima init --repo git@github.com:you/foo.git
dejima ls                          # one row per island, last-used first
dejima connect foo                 # drops into Claude Code, in foo's island
# Ctrl-b d to detach. Or just close the terminal — session keeps running.

DEJIMA_HOST=mac-mini.tailnet:7273 dejima connect foo   # from your laptop

Why it's worth it: islands are real containers. Each has its own $HOME, its own git config, its own gh credentials, its own working directory. Cross-pollination between projects isn't a discipline thing — the kernel won't let it happen. And because sessions are tmux-backed, your laptop closing or your network blipping doesn't kill anything; you reattach where you left off, from wherever you are.

Use case: Product builder

If you're building a product on top of agent CLIs — a multi-agent dashboard, a chat-driven coding bot, a web IDE, a team-internal tool — Dejima is the execution substrate so you don't reinvent container lifecycle, PTY multiplexing, session management, and credential injection for your one product.

# Target the Dejima HTTP API from any language.
POST   /v1/islands          { "repo": "...", "agent": "claude-code" }
GET    /v1/islands          # list all islands
GET    /v1/islands/:name/session       # websocket PTY stream, multi-attach
POST   /v1/islands/:name/exec          # one-shot command
POST   /v1/events/subscribe { "url": "https://yourapp.example.com/events" }

Why it's worth it: the boring substrate work — container lifecycle, host-side PTY, multi-client multiplexing, credential injection, webhook events, service install, Tailscale-pinned remote access — is done and OSS. You build the interesting part. The same API the CLI uses is the one you target; if a feature exists in dejima, it exists for you too.

Use case: Self-hosted privacy / compliance

If you can't or won't ship your code to a third-party agent service — NDA work, regulated industries (medical, financial, defense, legal), client confidentiality, or just principle — Dejima runs entirely on your hardware. The agent's LLM API calls go out (that's how agents work at all), but your repo, your generated files, and your auth never leave your box.

# Install on a regulated server.
curl -fsSL https://aoos.github.io/dejima/install.sh | bash

# Tailscale-pin the daemon's remote port. Off-tailnet connections are refused.
dejimad --tcp :7273

Why it's worth it: your code, your workspace, your generated artifacts stay on your disk. Network egress is yours to set — block what you want, allow only LLM endpoints if your policy demands it. Auth is via Tailscale identity, not a vendor cloud's account model. When you're done, dejima purge erases the island. No data on someone else's bill.

Dejima isn't a replacement for tmux — it uses tmux inside each island. It's the layer above that adds isolation, lifecycle verbs (hibernate / reset), webhook events, and the cross-device API.

CLI reference

CommandPurpose
dejima initProvision a new island.
dejima connectAttach to an island's session (multi-attach).
dejima lsList all islands.
dejima statusOne island in detail: presence, memory, CPU.
dejima hibernate / wakeStop / restart the container; volumes preserved.
dejima resetClear agent state. Preserves workspace.
dejima exec / cp / logsOne-shot command, file copy, log tail — no session attach.
dejima doctorHealth check: daemon, Docker, image, projects, webhooks.
dejima serviceInstall / uninstall dejimad as a host service.
dejima webhookSubscribe a URL to receive state-change events.
dejima purgeDestroy island and volumes.

Webhooks

Subscribe a URL to get JSON POSTs on lifecycle events (island.hibernated, island.woken, …), presence (client.attached, client.detached), and agent-specific events (agent.waiting-for-input, agent.task-complete via the Claude Code shim). This is how mobile push, Slack notifications, and custom dashboards integrate.

dejima webhook subscribe --url https://ntfy.sh/your-private-topic
