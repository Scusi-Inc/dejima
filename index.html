Dejima

The persistent runtime for isolated AI agents — reachable from every device, on hardware you own. pre-alpha

Dejima was an artificial island built in 1636 in Nagasaki Bay to serve as a quarantined trading post for foreigners during Japan's period of isolation.

Dejima is the missing layer for running AI coding agents on your own infrastructure. Each project lives in its own island — an isolated container with an agent — accessible from any of your devices.

In other words: it lets you run a bunch of Claude Code sessions on your own Mac mini or server without losing your mind to tmux.

Managing multiple instances of Claude Code shouldn't require manually provisioning tmux sessions, fighting SSH drops, and wrestling with folder permissions for every parallel task. You shouldn't have to baby your environment just to let an agent work in the background. There's a better way.

Architecture

┌──────────────────────────┐
│  Control plane / UI      │   CLI · TUI · Dispatch · your app
└────────────┬─────────────┘
             │  websocket + HTTP API, over Tailscale
             ▼
┌──────────────────────────┐
│  Dejima runtime          │   Mac mini · VPS · cloud VM
└────────────┬─────────────┘
             │  isolation boundary
             ▼
┌──────────────────────────┐
│  Agent in an island      │   one container per project
└──────────────────────────┘

Inside each island, the agent process runs under a long-lived tmux session — that's what keeps it alive when no client is attached, and how multiple clients can share the same screen. The daemon bridges your websocket to that tmux session via a host-side PTY, which handles terminal sizing, multi-client multiplexing, and clean detach on disconnect.

Install

Pick where you're installing it. The page rewrites itself for your choice.

I'm setting up a
on

Mac mini, MacBook, anything running macOS that will run the islands.

  1. Open Terminal. Cmd-Space → type Terminal → Enter. Any directory is fine — the installer uses ~/.dejima-src.
  2. Install Tailscale (required for remote access; skip if installed): 
    brew install tailscale
sudo tailscale up                # opens a browser, sign in to your tailnet
  3. Install Dejima: 
    curl -fsSL https://aoos.github.io/dejima/install.sh | bash

    Bootstraps Go + Docker Desktop if missing, builds the binaries, installs them to /usr/local/bin, builds the island image, registers dejimad as a launchd service, runs dejima doctor. Idempotent — re-run to update.

  4. (Optional) Phone push notifications: 
    dejima service install --notify https://ntfy.sh/your-private-topic
  5. Open the dashboard: 
    dejima                              # interactive TUI

Linux box (always-on home server, VPS, etc.) that will run the islands.

  1. Open a terminal. Your usual one. Any directory is fine — the installer uses ~/.dejima-src.
  2. Install Docker (required, not bootstrapped by the installer): 
    sudo apt install docker.io          # Debian / Ubuntu
# sudo dnf install docker            # Fedora
# sudo pacman -S docker              # Arch
sudo systemctl enable --now docker
sudo usermod -aG docker $USER       # then log out + back in
  3. Install Tailscale (required for remote access from other devices): 
    curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up                   # opens a URL, sign in to your tailnet
  4. Install Dejima: 
    curl -fsSL https://aoos.github.io/dejima/install.sh | bash

    Installs binaries to /usr/local/bin, builds the island image, registers dejimad as a systemd user unit, runs dejima doctor. Idempotent.

  5. (Optional) Phone push notifications: 
    dejima service install --notify https://ntfy.sh/your-private-topic
  6. Open the dashboard: 
    dejima                              # interactive TUI

The Dejima server is Unix-only. The daemon needs Docker + tmux, which means macOS or Linux. Use a Mac mini, an always-on Linux box, or a VPS as your server. Your Windows PC can still be a client — pick Client above.

Mac laptop / desktop that will connect to a remote Dejima server.

  1. Open Terminal. Cmd-Space → Terminal → Enter.
  2. Install Tailscale, sign in to the same tailnet as the server: 
    brew install tailscale
sudo tailscale up
  3. Install the Dejima client (just the dejima CLI — no Docker, no daemon): 
    curl -fsSL https://aoos.github.io/dejima/install-client.sh | bash
  4. Find your server's tailnet address. On the server, run: 
    tailscale ip -4                     # e.g. 100.84.12.7   (foolproof)
tailscale status --self             # e.g. mac-mini.tailXXXXX.ts.net

    Either works — the 100.x.y.z IP avoids any MagicDNS gotchas.

  5. Point the client at the server (persisted): 
    echo 'export DEJIMA_HOST=100.84.12.7:7273' >> ~/.zshenv
export DEJIMA_HOST=100.84.12.7:7273
  6. Open the dashboard: 
    dejima                              # interactive TUI

  1. Open PowerShell. Start menu → type PowerShell → Enter. Any directory is fine.
  2. Install Tailscale from tailscale.com/download/windows (GUI installer) and sign in to the same tailnet as your server.
  3. Install the Dejima client (downloads dejima.exe to %LOCALAPPDATA%\dejima, adds it to your PATH):

  6. Close + reopen PowerShell so the new PATH and DEJIMA_HOST are picked up.

    dejima                              # interactive TUI

Use case: Home server

If you run AI agents over ssh on a home server — Mac mini, VPS, an always-on Linux box on your shelf — Dejima is the layer that fixes the parts of that workflow that suck.

Each project gets a named island. dejima init derives the name from the repo, dejima ls shows everything at a glance, and dejima connect <name> is the same command every time. No tmux mnemonics to memorize. No claude1/claude2 ambiguity.

dejima init --repo git@github.com:you/foo.git
dejima ls                          # one row per island, last-used first
dejima connect foo                 # drops into Claude Code, in foo's island
# Ctrl-b d to detach. Or just close the terminal — session keeps running.

DEJIMA_HOST=mac-mini.tailnet:7273 dejima connect foo   # from your laptop

Or skip the commands entirely. Run dejima with no arguments for an interactive dashboard: live state and presence for every island, single-key lifecycle (connect / hibernate / wake / reset / purge), and n to launch a new one — it scans your code folder, lists your repos with their git status, and provisions an island in a couple of keystrokes. Press ? for the full key map.

dejima                             # interactive dashboard
#  n  → pick a repo, choose an agent (Claude Code / Codex), launch
#  ⏎  → attach   ·   h hibernate   ·   ?  help

Repos can come from anywhere: a git URL, or a local checkout already on disk — Dejima clones from its remote by default, or seeds from your working copy (--local-copy) to capture unpushed work. And one repo can back several islands at once — Claude Code and Codex side by side, or two agents on parallel tasks.

Why it's worth it: islands are real containers. Each has its own $HOME, its own git config, its own gh credentials, its own working directory. Cross-pollination between projects isn't a discipline thing — the kernel won't let it happen. And because sessions are tmux-backed, your laptop closing or your network blipping doesn't kill anything; you reattach where you left off, from wherever you are.

Use case: Product builder

If you're building a product on top of agent CLIs — a multi-agent dashboard, a chat-driven coding bot, a web IDE, a team-internal tool — Dejima is the execution substrate so you don't reinvent container lifecycle, PTY multiplexing, session management, and credential injection for your one product.

It's the persistent runtime layer for agent-native work — your control plane (a UI, a bot, the CLI) on top, your compute underneath, isolation in between. The boring middle is done and OSS; you build the interesting part.

# Target the Dejima HTTP API from any language.
POST   /v1/islands          { "repo": "...", "agent": "claude-code" }
GET    /v1/islands          # list all islands
GET    /v1/islands/:name     # live detail: presence, cpu/mem, git, crash health
GET    /v1/islands/:name/session       # websocket PTY stream, multi-attach
POST   /v1/islands/:name/exec          # one-shot command
POST   /v1/events/subscribe { "url": "https://yourapp.example.com/events" }

Why it's worth it: the boring substrate work — container lifecycle, host-side PTY, multi-client multiplexing, credential injection, webhook events, service install, Tailscale-pinned remote access — is done and OSS. You build the interesting part. The same API the CLI uses is the one you target; if a feature exists in dejima, it exists for you too. Full surface documented at the API reference.

Use case: Self-hosted privacy / compliance

If you can't or won't ship your code to a third-party agent service — NDA work, regulated industries (medical, financial, defense, legal), client confidentiality, or just principle — Dejima runs entirely on your hardware. The agent's LLM API calls go out (that's how agents work at all), but your repo, your generated files, and your auth never leave your box.

# Install on a regulated server.
curl -fsSL https://aoos.github.io/dejima/install.sh | bash

# Expose the daemon to your tailnet (off-tailnet connections are refused).
# Bakes --tcp into the service so remote access survives reboots.
dejima service install --tcp :7273

Why it's worth it: your code, your workspace, your generated artifacts stay on your disk. Network egress is yours to set — block what you want, allow only LLM endpoints if your policy demands it. Auth is via Tailscale identity, not a vendor cloud's account model. When you're done, dejima purge erases the island. No data on someone else's bill.

Dejima isn't a replacement for tmux — it uses tmux inside each island. It's the layer above that adds isolation, lifecycle verbs (hibernate / reset), webhook events, and the cross-device API.

CLI reference

CommandPurpose
dejimaInteractive dashboard — browse, manage, and launch islands. n new · ? help.
dejima initProvision a new island from a git URL or a local path.

dejima lsList all islands.

dejima exec / cp / logsOne-shot command, file copy, log tail — no session attach.

dejima webhookSubscribe a URL to receive state-change events.
dejima purgeDestroy island and volumes.

Webhooks

Subscribe a URL to get JSON POSTs on lifecycle events (island.hibernated, island.woken, …), presence (client.attached, client.detached), and agent-specific events (agent.waiting-for-input, agent.task-complete via the Claude Code shim). This is how mobile push, Slack notifications, and custom dashboards integrate.

dejima webhook subscribe --url https://ntfy.sh/your-private-topic

Concepts

TermMeaning
IslandThe container holding a single project and a single agent.
BridgeThe brokered I/O channel between host and island.
Trade(planned) A brokered, synced export of changes from island to host.
Intake(planned) Files brokered into the island from the host.
Ledger(planned) An audit log of every brokered transaction.

Intake / Trade / Ledger are the planned brokered-context primitives — the seam a memory or context layer attaches to without breaking island isolation. See the positioning note.
