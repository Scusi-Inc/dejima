Dejima

The secure runtime for isolated AI agents — a fleet per project, on hardware you own. pre-alpha

Dejima was an artificial island built in 1636 in Nagasaki Bay to serve as a quarantined trading post for foreigners during Japan's period of isolation.

Dejima is the secure substrate for running AI agents on hardware you control — it manages the isolated containers, sessions, and credentials, so each project runs one or more agents together, sandboxed from your machine and from each other, behind one clean API.

Running agents on a Mac mini or server?

Dejima is your own agent server — run a fleet of Claude Code / Codex agents, each sandboxed in its own container; the ones on a project share credentials, so you permission them once. Live state and simple controls on one dashboard.

Six agents in tmux you can't tell apart, context bleeding between projects, re-authing every one — and one bad command from touching the wrong repo.

Run agents securely on your own box

Several Claude Code / Codex agents per project, each sandboxed in its own container — no context bleed, no agent trashing your host or another repo. Each on its own git worktree; agents in the same project share one set of credentials, so you permission them once. See every agent's state at a glance and manage them with simple controls.

Building a product on top of agents?

Dejima is your agent backend — one API for isolated containers, sessions, lifecycle, real-time agent status events, and management controls, without building any of it.

Shipping on agents shouldn't mean reinventing container lifecycle, PTY multiplexing, session management, and per-agent auth from scratch.

Build services on isolated, secured agents

Multi-agent dashboards, chat-driven coding bots, web IDEs, internal tools. Target one HTTP/WebSocket API and get isolated containers, multi-attach sessions, lifecycle, credential injection, agent-state events & analytics, and management controllers — instead of reinventing them.

The installers below handle Tailscale (offer to install it, walk you through sign-in) and — on the client side — capture the server's address into DEJIMA_HOST for you. No manual steps in between.

Server on macOS. Mac mini (typical), or any always-on Mac. The Dejima daemon runs here; other devices connect to it.

  1. Open Terminal. Press ⌘-Space, type Terminal, hit Enter. Any working directory is fine — the installer uses ~/.dejima-src regardless.
  2. Run the installer: 
    curl -fsSL https://aoos.github.io/dejima/install.sh | bash

    It does all of this in order:

    • Offers to install Tailscale (Homebrew) if missing, then walks you through sudo tailscale up — a browser tab opens to sign in to your tailnet.
    • Offers to install Docker Desktop (or detects OrbStack / colima) — needed to run islands.
    • Builds the dejima + dejimad binaries, installs them to /usr/local/bin, builds the island image, registers dejimad as a launchd service, runs dejima doctor.
    • Captures the server's tailnet IP into ~/.dejima/host.json and prints the DEJIMA_HOST string you'll use on your other devices.

    Idempotent — re-run any time to update or finish a partial run.

  3. (Optional) Get push notifications on your phone when islands change state: 
    dejima service install --notify https://ntfy.sh/your-private-topic
  4. Open the dashboard: 
    dejima                              # interactive TUI

Note the DEJIMA_HOST the installer prints (something like 100.84.12.7:7273) — you'll plug it into the client setup on your other devices.

Server on Linux. Always-on home server, VPS, or any Linux box. The Dejima daemon runs here; other devices connect to it.

  1. Open a terminal. Your usual one (GNOME Terminal, Konsole, Alacritty, an SSH session, whatever). Any working directory is fine — the installer uses ~/.dejima-src.
  2. Install Docker (the installer doesn't bootstrap Docker on Linux): 
    sudo apt install docker.io          # Debian / Ubuntu
# sudo dnf install docker            # Fedora
# sudo pacman -S docker              # Arch
sudo systemctl enable --now docker
sudo usermod -aG docker $USER       # log out + back in for group to take effect
  3. Run the installer: 
    curl -fsSL https://aoos.github.io/dejima/install.sh | bash

    It does all of this in order:

    • Offers to install Tailscale (official install script) if missing, then walks you through sudo tailscale up.
    • Builds the dejima + dejimad binaries, installs them to /usr/local/bin, builds the island image, registers dejimad as a systemd user unit, runs dejima doctor.
    • Captures the server's tailnet IP into ~/.dejima/host.json and prints the DEJIMA_HOST string for your other devices.

    Idempotent — re-run any time.

  4. (Optional) Phone push notifications: 
    dejima service install --notify https://ntfy.sh/your-private-topic
  5. Open the dashboard: 
    dejima                              # interactive TUI

Note the DEJIMA_HOST the installer prints — you'll plug it into the client setup on your other devices.

The Dejima server is Unix-only. The daemon needs Docker + tmux, which means macOS or Linux. Use a Mac mini, an always-on Linux box, or a VPS. Your Windows PC can still be a client — pick Client above.

Client on macOS. Mac laptop or desktop that will connect to your remote Dejima server.

  1. Open Terminal. ⌘-Space → Terminal → Enter.
  2. Run the client installer: 
    curl -fsSL https://aoos.github.io/dejima/install-client.sh | bash

    It does all of this in order:

    • Offers to install Tailscale if missing, then walks you through sudo tailscale up — sign in to the same tailnet as your server.
    • Downloads the latest dejima CLI from GitHub Releases, verifies SHA256, installs to /usr/local/bin/dejima.
    • Prompts for your server's tailnet IP (the one the server installer printed — e.g. 100.84.12.7), probes it on port 7273, and persists DEJIMA_HOST to ~/.zshenv.
  3. Open the dashboard: 
    dejima                              # interactive TUI

  2. Run the client installer:

    It does all of this in order:

    • Offers to install Tailscale (official install script) if missing, then walks you through sudo tailscale up — sign in to the same tailnet as your server.

  3. Open the dashboard:

Client on Windows. Windows PC that will connect to your remote Dejima server. The daemon is Unix-only, but the client CLI runs on Windows.

  1. Open PowerShell. Press the Windows key, type PowerShell, press Enter. Any working directory is fine.
  2. Run the client installer: 
    irm https://aoos.github.io/dejima/install-client.ps1 | iex

    It does all of this in order:

    • Offers to install Tailscale via winget if missing. Then points you at the system-tray icon: right-click → Log in, sign in to the same tailnet as your server. (Tailscale sign-in is GUI-driven on Windows, so the installer can't fully automate it.)
    • Downloads dejima.exe from the latest GitHub Release, verifies SHA256, extracts to %LOCALAPPDATA%\dejima, and adds it to your User PATH.
    • Prompts for your server's tailnet IP, probes it on port 7273 via Test-NetConnection, and persists DEJIMA_HOST to your User environment.
  3. Close + reopen PowerShell so the new PATH and DEJIMA_HOST take effect.
  4. Open the dashboard: 
    dejima                              # interactive TUI

Use case: Run it yourself

One line to install on the server, one word to run. The installer handles Tailscale, Docker, and the service (per-platform steps in Install).

curl -fsSL https://aoos.github.io/dejima/install.sh | bash   # on the server, once
dejima                                                       # the dashboard

# In the dashboard:
#   n → pick a repo + agent, launch       + → add another agent
#   ⏎ → open an island/agent in a window   ? → all keys

Every dashboard action is also a one-shot command:

dejima init --repo git@github.com:you/foo.git    # or --local-copy for unpushed work
dejima ls                                         # all islands, last-used first
dejima agent add foo --type codex                 # a 2nd agent in foo's island
dejima connect foo                                # attach (Ctrl-b d detaches)
DEJIMA_HOST=mac-mini.tailnet:7273 dejima connect foo   # …from your laptop

Why self-hosted: privacy & compliance

The LLM calls go out, but your code, files, and auth never leave your box. Egress is yours to set; auth is your Tailscale identity, not a vendor account; dejima purge erases an island when you're done. Fits NDA, regulated, and client-confidential work.

Use case: Build services on the API

Your control plane (a dashboard, a bot, the CLI) on top; your compute underneath; isolation in between. Target one HTTP/WebSocket API from any language — the same one the CLI uses.

POST   /v1/islands                     { "repo": "...", "agent": "claude-code" }
GET    /v1/islands                      # list all islands
GET    /v1/islands/:name                # live detail: agents, presence, cpu/mem, git, health
POST   /v1/islands/:name/agents         { "type": "codex" }   # add an agent
GET    /v1/islands/:name/agents/:id/session   # websocket PTY stream, multi-attach
POST   /v1/islands/:name/exec           # one-shot command
POST   /v1/events/subscribe { "url": "https://yourapp.example.com/events" }

The substrate — container lifecycle, PTY multiplexing, credential injection, events, remote access — is done and OSS. Full surface at the API reference.

Architecture

        CLI · TUI · Dispatch · your app        (control plane)
                    │
                    │  websocket + HTTP API · over Tailscale
                    ▼
┌─ Dejima host · Mac mini / VPS / cloud VM ──────────────────────┐
│                                                                │
│   ┌─ island: web ──────────┐    ┌─ island: api ──────────┐     │
│   │ a1  claude-code        │    │ a1  codex              │     │
│   │ a2  codex              │    │ a2  claude-code        │     │
│   │ a3  headless           │    │                        │     │
│   └────────────────────────┘    └────────────────────────┘     │
│                                                                │
│ per island: one container · shared home + credentials          │
│ per agent:  own git worktree · sandboxed from host & others    │
└────────────────────────────────────────────────────────────────┘

An island is one container holding one or more agents. They share the workspace, credentials, and tool-auth, but each works on its own git worktree — so they collaborate without clobbering each other.

Two kinds of agents. Terminal agents are CLIs you attach to (Claude Code, Codex) — a host-side PTY bridges your websocket to the agent's tmux session, so it survives detach and multiple devices share one screen. Headless agents run on their own (a Python SDK loop, a worker) — output captured to dejima logs. Both get the same isolation, lifecycle, events, and one-API management.

"API" here means Dejima's HTTP/WebSocket control surface — what your CLI, dashboard, or phone client targets. The LLM APIs (Anthropic, OpenAI) are reached by the agents inside islands, on their own.

Dejima isn't a replacement for tmux — it uses tmux inside each island. It's the layer above that adds isolation, lifecycle verbs (hibernate / reset), webhook events, and the cross-device API.

Webhooks

Subscribe a URL to get JSON POSTs on lifecycle events (island.hibernated, island.woken, …), presence (client.attached, client.detached), and agent-specific events (agent.waiting-for-input, agent.task-complete) emitted by the per-agent shims — Claude Code and Codex today, headless agents on their own via POST /v1/internal/agent-event. This is how mobile push, Slack notifications, and custom dashboards integrate. See docs/agent-adapters.md for adding your own.

dejima webhook subscribe --url https://ntfy.sh/your-private-topic

Uninstall

Get your work out first. Dejima never touches your host folders — but work done inside an island lives in that island's Docker volume, and dejima purge destroys it. Before removing anything, make sure each island's work is pushed to its remote (or copied out):

dejima exec foo -- git status        # anything uncommitted or unpushed?
dejima exec foo -- git push          # send it to your remote
dejima cp foo:/workspace/file ./     # or copy files out directly

Then remove Dejima from the server:

dejima purge <name>                  # each island: container + volumes
dejima service uninstall             # stop + deregister the daemon
sudo rm /usr/local/bin/dejima /usr/local/bin/dejimad
rm -rf ~/.dejima ~/.dejima-src       # state + config, source checkout

On a client device, uninstalling is just deleting the dejima binary and removing DEJIMA_HOST from your shell profile. Docker and Tailscale are left in place — Dejima uses them but didn't install-own them; remove them separately if nothing else needs them.

Concepts

TermMeaning
IslandThe container holding one project and one or more agents.
AgentOne CLI (Claude Code, Codex) or headless process inside an island, on its own git worktree.
BridgeThe brokered I/O channel between host and island.
Trade(planned) A brokered, synced export of changes from island to host.
Intake(planned) Files brokered into the island from the host.
Ledger(planned) An audit log of every brokered transaction.

Intake / Trade / Ledger are the planned brokered-context primitives — the seam a memory or context layer attaches to without breaking island isolation. See the positioning note.
